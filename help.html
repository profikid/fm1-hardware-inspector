HELP! I BRICKED IT

FM-1 · SMK-37 PRO · SMK-37 ELITE // RECOVERY GUIDE
READ FIRST
DON'T PANIC. DON'T KEEP FLASHING RANDOM FIRMWARE.

A black screen does not automatically mean dead hardware. The JieLi chip has a built-in USB download mode that can still work when the synth firmware is broken.

First rule: use a USB data cable, connect directly (no hub), and do not disconnect while a flash or verification is running. If Windows asks to format UBOOT1.00 / WL82 UBOOT1.00, click Cancel.

01 / TRIAGE — WHAT DOES THE COMPUTER SEE?

A · USB DEVICE APPEARS

A disk/device called UBOOT1.00 or WL82 UBOOT1.00 appears, or the synth still appears as USB MIDI.

Good news: start with M-Flasher. No RP2040 wiring should be needed.

B · NOTHING APPEARS

No USB MIDI device and no UBOOT disk after trying a known-good data cable, another port and a power cycle.

This is the hard-brick path. You may need a USB_KEY / RP2040 recovery device to force the chip into ROM download mode.

On macOS the ROM device may appear as an unreadable removable disk. Do not initialize or erase it. On Windows check Device Manager or Disk Management; do not format it.

02 / THE NORMAL RESCUE — M-FLASHER

DOWNLOAD M-FLASHER SOURCE + DOCUMENTATION

  1. Download the latest release for Windows, macOS or Linux. Install / extract it using the release's instructions. The app is unofficial and unsigned; only download it from the project's GitHub Releases.
  2. Connect the FM-1 or SMK-37 directly with a USB data cable and power it on.
  3. If firmware is running: open M-Flasher. It should find the unit over USB MIDI. Press DOWNLOAD MODE in M-Flasher. This sends the device into the chip's ROM download mode.
  4. If m-bootloader is installed: switch off, hold REC (FM-1) or SEQ REC (SMK-37), then switch on while holding the key.
  5. If Felucca, SLOOP or Snoop37 is running: hold OCT− + OCT+ for 5 seconds.
  6. Wait for M-Flasher to identify the device and read its flash. Check the reported model and flash chip. If it cannot confidently identify the board, stop; do not force the wrong board.
  7. Choose Back up the whole flash before writing anything. Keep the generated backup and JSON report somewhere safe. This contains factory calibration, Bluetooth identity/pairings, presets and user data.
  8. For a straightforward recovery, choose Install firmware and select the official .fwsc package for the exact model: FM-1, SMK-37 Pro or SMK-37 Elite. Review the flash map and the proposed changes before confirming.
  9. Let the write and verification finish. Do not unplug, power off, close the app or let the computer sleep during the operation.
  10. When M-Flasher reports success, unplug, switch off, wait 5 seconds, then power on. If it boots, make another backup before experimenting again.
Do not select “erase settings / Bluetooth” casually. That can remove pairings and user settings. Do not restore another person's full-flash image as if it were yours; use your own backup so your device's factory data is preserved.

03 / INSTALL M-BOOTLOADER — PREVENT THE NEXT BRICK

M-BOOTLOADER RELEASES README + SPEC

m-bootloader adds a key-triggered download mode and a recovery menu. It supports FM-1 and SMK-37 Pro / Elite, but the boot image is board-specific.

  1. First make a complete M-Flasher backup. Do not skip this.
  2. Download the current m-bootloader release and select the correct image: fm1-uboot.boot for FM-1, or smk37-uboot.boot for SMK-37 Pro / Elite.
  3. In M-Flasher, open the bootloader action/tab, choose the matching .boot file and inspect the flash map. The bootloader operation should change only the boot area.
  4. Confirm only if M-Flasher identifies the correct model and chip key and the proposed write is limited to the boot area. Allow the write verification to complete.
  5. Power-cycle. Test the recovery menu: hold PLAY (FM-1) or SEQ PLAY (SMK-37) while powering on.

M-VAVE official updates and some custom firmware installers can put the stock bootloader back. If that happens, reinstall m-bootloader after making a fresh backup.

04 / RECOVERY MENU — WHEN FIRMWARE WILL NOT START

With m-bootloader installed, hold PLAY (FM-1) or SEQ PLAY (SMK-37) during power-on. If the firmware cannot start, the menu can also open by itself.

  • Download mode: safest route for M-Flasher to inspect, back up and reinstall firmware.
  • MIDI mode: lets a compatible browser installer communicate over USB MIDI, even if the main firmware is not running. Keep the installer tab in the foreground; it may read the package twice.
  • Boot app: tries the installed firmware. Use only when you know what is installed and why it failed.
  • Boot anyway: bypasses a checksum failure once. This is not a repair; avoid it unless you understand the image and accept the risk.
  • Wipe user data: erases only firmware-declared settings ranges, but still deletes data. It is not the first recovery step.

For MIDI-mode reinstall, use the installer supplied by the firmware project and make sure it explicitly supports your exact model. If an install is interrupted, do not pull the cable mid-write. Follow that installer's resume/reconnect instructions.

05 / HARD BRICK — NO USB DEVICE AT ALL

Stop here if you're not comfortable with USB wiring. The next step uses a small RP2040 board / USB_KEY-style device to force the chip's ROM into download mode. It is not a firmware file you copy to the synth.

FM-1

Use the FM-1 Transporter or the FM-1 Unbricker guide. The Transporter uses an RP2040 board and a modified USB cable to assert the chip's recovery signal. Follow the repository's wiring diagram exactly; do not guess pins. Once ROM download mode appears, use M-Flasher for the backup and recovery if it recognizes the unit.

SMK-37 Pro / Elite

The SMK community has documented an RP2040-based route to force ROM download mode. The Reddit workflow reports the device appearing as UBOOT1.00, then uses the SMK's own firmware package and an SMK-specific extraction range. That is not the FM-1 unbrick script.

Prefer this order: force ROM mode using a verified hardware guide → connect directly → let current M-Flasher identify the SMK-37 → make a full backup → use the model-matched SMK-37 firmware package. If M-Flasher does not recognize the board, stop and follow the SMK-specific community thread with care rather than running FM-1 commands against it.

SMK-37 community hard-brick walkthrough SMK-37 ROM-mode discussion

CRITICAL MODEL WARNING

MvaveFM1Unbricker is an FM-1 recovery project. Its author explicitly documents that the SMK-37 flash ID differs and the FM-1 restore script refuses it. Do not force the FM-1 firmware image, flash offsets or extraction script onto an SMK-37. The SMK-37 Reddit procedure is community-reported and is not a substitute for model validation by M-Flasher.

06 / KNOWN TRAPS FROM THE COMMUNITY

  • Don't interrupt a stalled write immediately. Reddit reports several cases where disconnecting during a frozen update caused a black-screen device. Give the installer time and use its documented resume path.
  • Stock firmware between custom firmwares. One community workflow recommends returning to official stock firmware between different custom firmware families rather than flashing one custom image directly over another. Keep a backup first.
  • SMK-37 is not an FM-1. Same AC791N family does not mean identical board configuration, model identity or firmware package. Use Pro/Elite packages deliberately.
  • SMK-37 factory data matters. Calibration and Bluetooth/preset regions may be affected by custom installers. Back up before trying Baud Girl or switching firmware families.
  • Newer FM-1 flash chips: some late-2026 units report JEDEC 0xB36014. m-bootloader support on that chip has limited hardware testing; read the warning in its current README and check the chip ID before installing it.
